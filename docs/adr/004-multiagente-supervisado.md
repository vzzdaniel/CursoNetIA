# ADR 004 Flujo multiagente supervisado

- Estado: aceptada.
- Contexto: una única conversación puede arrastrar supuestos erróneos desde diseño hasta pruebas. Añadir agentes sin delimitar contexto, permisos y responsabilidad puede multiplicar errores, costo y cambios concurrentes.
- Decisión: adoptar consulta separada y síntesis inspiradas en Lokomotiv, usando capacidades documentadas de Copilot. El ingeniero fija expediente y criterios; dos lectores asignados para la ronda (Arquitecto, Revisor o Pruebas) entregan A/B sin recibir la respuesta del otro. El coordinador conserva desacuerdos y puede guardar únicamente el expediente `docs/expedientes/<ID>.md` y su paquete común separado tras mostrar rutas y contenido/diff y recibir confirmación humana de cada guardado. El ingeniero decide; un implementador modifica código, pruebas y documentación técnica. Pruebas y revisor evalúan evidencia en sesiones separadas. Cierre humano; confirmar un guardado no equivale a autorizar implementación ni aceptar el cambio.
- Ruta principal: perfiles de Visual Studio y coordinación manual explícita. Ruta opcional: Copilot CLI `/fleet` para análisis con perfiles específicos, herramientas de lectura y evidencia de subagentes reales. No instalar Lokomotiv ni afirmar integración nativa.
- Alternativas: una sola conversación cuesta menos pero favorece el arrastre de supuestos; escritores paralelos elevan coordinación/conflictos; aprobar por mayoría no demuestra corrección. Mantener una consulta manual de respaldo permite trabajar sin CLI, modelos adicionales o automatización.
- Consecuencias: registrar estado, respuestas originales y modelos aumenta el trabajo de revisión; acotar rondas al riesgo. El mismo modelo en varias sesiones no garantiza diversidad. La arquitectura .NET, las invariantes y los patrones seleccionados siguen requiriendo justificación propia; más agentes no sustituyen pruebas ni criterio.
- Evidencia: [protocolo y configuración](../multiagente-copilot.md), [harness](../harness-copilot.md), perfiles, prompts, registro de cambios y resultados reales del repositorio de trabajo. Los archivos prueban configuración propuesta; sólo una sesión observada acredita carga de herramientas y delegación.
- Revisar cuando cambien las capacidades/políticas de Copilot o cuando las rondas no aporten hallazgos suficientes para su costo.
